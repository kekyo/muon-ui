# Local asset configuration

Local assets are one of muon's characteristic features.
They let you reference locally placed built asset files through the special URL scheme `asset://`.

When you use the muon Vite plugin, you usually do not need to think about this much, but it is useful to know how a muon app displays pages.
Vite builds the web application source code and places it in `dist/`.
Then:

1. When `npm run dev` is executed, the contents of `dist/` are served as `http://localhost:5173/`, and muon displays that. As a result, `http://localhost:5173/index.html` is referenced.
2. When a muon app is run with `npx muon run`, muon makes the contents of `dist/` directly available as `asset://main/`. As a result, `asset://main/index.html` is referenced.
3. When a muon app generated by `npm run build`, such as `dist-muon/linux-amd64/`, is executed, the asset files are directly available as `asset://main/`. As a result, `asset://main/index.html` is referenced. In this case, the asset files are referenced from `assets.zip`, which packs those files, not from `dist/`.

Case 1 is needed to improve the HMR debugging experience provided by Vite.
Only when launched for development from Vite does the URL origin become the Vite server (`http://localhost:5173/`).
Cases 2 and 3 are closer to the distributed muon app state, and the URL origin is `asset://main/`.

Because the URL origin changes this way, take care when implementing a muon app.
For example, code that determines the current URL by assuming `http://localhost:5173/` will stop working correctly as soon as the app is built as a muon app.
Developers who normally use Vite are already used to URL origins changing after deployment, so this should not feel very surprising.
